Reading from and writing to the console.

Output needs no capability — it is always available. print and println take any type that satisfies Display: println(42), println(true), println("hi").

print function

pub fn print<T :: [Display]>(value: T): void

Writes any displayable value without a line break: print(42), print("hi").

There is no overloading; the Display constraint does the same job and extends to every type that satisfies it rather than to a fixed list. Monomorphization turns the call into a direct one per used type, so the generality costs nothing at runtime.

Nothing is flushed. A prompt written with print sits in the buffer until flush, which is why prompt exists.

readLine function

pub fn readLine(): ?string

Reads one line from standard input, without its line break.

null at end of input. Optional rather than an empty string, because EOF is a state and not a line: a program reading until null stops, one reading until "" never does.

Whether standard input and output are a terminal rather than a pipe.

A program writing into a pipe should not put a prompt into the stream, and this is how it knows.

flush function

pub fn flush(): void

Pushes buffered output to the console.

Needed as soon as something is written without a line break and has to be visible before the program continues — a prompt being the usual case.

prompt function

pub fn prompt(text: string): ?string

Writes text, flushes it, and reads one line.

The flush is the point: without it the question would sit in the buffer while the program waits for an answer nobody knows is expected. null at end of input, as readLine.

LineIterator class

The iterator lines hands out. Yields each line of standard input until it ends.

done: bool

Set once readLine answered null; from then on the iterator ends.

The next line, or null once the input has ended. Ends for good after the first null.

lines function

pub fn lines(): Iterator<string>

The lines of standard input, as an iterator — the idiomatic shape of a filter:

for (line in console.lines()) { … }

An iterator rather than a string[]: the input can be larger than memory, and a program that only counts should not have to collect it first.
