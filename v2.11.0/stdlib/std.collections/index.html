Indexable interface

pub interface Indexable<T>

What can be read and written with [i].

The same model as Iterator<T> for for-in: the compiler knows one built-in form — the array — and binds everything else to an interface from the standard library, so there is no special case per container type.

get and set are O(1). That is a requirement, not a description: an implementation with O(n) access must not satisfy this interface, or an index loop would be quadratic without showing it. string has no index operator for the same reason.

fn get(index: int): T

The value at index.

mut fn set(index: int, value: T): void

Replaces the value at index.

List class

pub class List<T> :: [Indexable<T>, Iterable<T>]

A growing list; a T[] has a fixed length, this does not.

Growing doubles and shrinking halves at a quarter, so push is amortized O(1) and a list oscillating around a boundary does not copy on every step.

data: (?T)[]

The backing slots; optional so a popped slot can actually release its value.

count: int

How many slots are filled.

pub fn length(): int

How many values are in it.

pub static fn empty(): List<T>

An empty list.

pub fn iter(): Iterator<T>

A fresh cursor on every call, so two loops over the same list do not disturb each other.

pub fn isEmpty(): bool

Whether nothing is in it.

pub fn capacity(): int

How many slots are allocated, empty ones included. For tests and for anyone measuring what the list costs; length is the truth for everything else.

pub mut fn push(value: T): void

Appends at the end; amortized O(1).

pub mut fn pop(): ?T

Removes and returns the last value, or null for an empty list — an ordinary state, unlike an index out of range.

pub fn get(index: int): T

The value at index. Out of range is a panic, as for an array: a programming error rather than a state.

pub mut fn set(index: int, value: T): void

Replaces the value at index. Out of range is a panic, as in get.

pub mut fn clear(): void

Empties the list. Every slot is released — nothing inserted stays alive — but the backing array is KEPT: a buffer emptied once per frame must not reallocate on every refill.

pub fn first(): ?T

The first value, or null for an empty list.

pub fn last(): ?T

The last value, or null for an empty list.

pub mut fn insert(index: int, value: T): void

Inserts at index, shifting everything from there one to the right. index == length() appends. Out of range is a panic, as in get.

pub mut fn removeAt(index: int): T

Removes and returns the value at index, shifting the rest left. Out of range is a panic, as in get.

pub mut fn reverse(): void

Reverses in place.

pub mut fn swap(a: int, b: int): void

Exchanges two positions. Out of range is a panic, as in get.

pub fn toArray(): T[]

A copy as a real array.

collect function

pub fn collect<T>(source: Iterator<T>): List<T>

Collects an iterator into a List<T>.

Here rather than in std.iter, because the dependency runs this way: std.collections imports std.iter, not the reverse. std.iter.collectArray is the variant without that dependency, and it is quadratic because a T[] copies on every append. This one doubles and is linear.

Map class

pub class Map<K :: [Hashable<K>], V>

A hash map: open addressing, linear probing, load factor 3/4. The key type says how to hash and how to compare — [Hashable<K>] — and the iteration order is UNSPECIFIED.

pub fn isEmpty(): bool

pub static fn empty(): Map<K, V>

An empty map, with room for the first insertions before a growth.

The value for the key, or fallback when the key is absent — one probe instead of a containsKey before every get.

sortListBy function

pub fn sortListBy<T>(xs: List<T>, less: fn(T, T) -> bool): void

Sorts in place with a comparison of your own.

less(a, b) must return true when a comes STRICTLY before b. A less returning true for equal elements destroys stability; a contradictory less makes the output arbitrary but crashes nothing, because the algorithm only compares.
